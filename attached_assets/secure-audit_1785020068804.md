Вот полный аудит безопасности проекта **Secure-Chat (Family Messenger)**, сгруппированный по критичности.

---

## АУДИТ БЕЗОПАСНОСТИ: Secure-Chat

### Общая оценка

Проект демонстрирует **хороший уровень безопасности** для MVP: используется Argon2id для хеширования PIN, Drizzle ORM исключает SQL-инъекции, JWT-токены хранятся в SecureStore, Docker-контейнер работает от непривилегированного пользователя, есть rate limiting и логирование с редактированием чувствительных данных. Критических уязвимостей не обнаружено. Найдены проблемы средней и низкой критичности.

## HIGH (2 находки)

### H1. CORS: `cors()` без ограничений — доступ с любого-origin
- **Файл:** `artifacts/api-server/src/app.ts:40`
- **Проблема:** `app.use(cors())` без аргументов = `Access-Control-Allow-Origin: *`. Любой сайт может делать API-запросы от имени авторизованного пользователя (если токен передаётся через Authorization header, CORS preflight разрешит кросс-origin запросы).
- **Риск:** Атакующий может разместить вредоносную страницу, которая будет отправлять запросы к API используя JWT-токен жертвы (при условии, что токен доступен JS).
- **Исправление:** Ограничить CORS белым списком Origins из переменной окружения:
  ```ts
  app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') ?? [] }));
  ```

### H2. WebSocket: отсутствует rate limiting на сообщениях
- **Файл:** `artifacts/api-server/src/ws/server.ts`, `ws/handlers.ts`
- **Проблема:** REST API имеет rate limiting (5/min на логин, 120/min на API), но WebSocket-сервер не имеет ограничений на количество сообщений. Авторизованный пользователь может отправлять произвольное количество сообщений через WS без какого-либо ограничения.
- **Риск:** DoS-атака со стороны авторизованного пользователя, исчерпание ресурсов сервера/БД.
- **Исправление:** Добавить простой пер-пользовательский rate limiter на WS-хендлерах (например, 30 сообщений/секунду).

## MEDIUM (5 находок)

### M1. HTTP-соединения разрешены клиентом — незашифрованный трафик
- **Файлы:**
  - `artifacts/messenger-android/app/server-config.tsx:34-35`
  - `artifacts/messenger-android/services/wsService.ts:71`
- **Проблема:** Клиент принимает `http://` URL. При `http://` сервере: JWT-токен, все сообщения и WebRTC signaling передаются открытым текстом. `wsService` преобразует `http://` → `ws://` (незашифрованный WebSocket).
- **Риск:** MITM-атака, перехват всех сообщений и токенов.
- **Исправление:** Запретить `http://` в production (разрешить только для `localhost`/`10.*` адресов) или показывать предупреждение.

### M2. JWT `verify` без явного указания алгоритма
- **Файлы:**
  - `artifacts/api-server/src/middlewares/auth.ts:39`
  - `artifacts/api-server/src/ws/server.ts:67`
  - `artifacts/api-server/src/routes/v1/auth.ts:164`
- **Проблема:** `jwt.verify(token, secret)` без `{ algorithms: ['HS256'] }`. Библиотека `jsonwebtoken` по умолчанию проверяет алгоритм из заголовка токена, что может быть использовано для атаки переключения алгоритма (algorithm confusion attack) если атакующий подделает заголовок токена.
- **Риск:** Подмена алгоритма подписи (HS256 → none или RS256).
- **Исправление:** Везде добавить `{ algorithms: ['HS256'] }`:
  ```ts
  jwt.verify(token, secret, { algorithms: ['HS256'] });
  ```

### M3. Данные пользователя в незашифрованном хранилище (AsyncStorage)
- **Файлы:**
  - `artifacts/messenger-android/context/AuthContext.tsx:55-58` — `user_id`, `user_name`
  - `artifacts/messenger-android/services/serverConfig.ts:11` — `server_url`
  - `artifacts/messenger-android/utils/deviceId.ts:12` — `device_id`
- **Проблема:** `user_id` и `user_name` хранятся в `AsyncStorage` (незашифрованное хранилище), хотя JWT-токен правильно хранится в `expo-secure-store`.
- **Риск:** На rooted/jailbroken устройствах эти данные доступны. Для family-мессенджера это не критично, но нарушает принцип минимальных привилегий.
- **Исправление:** Перенести `user_id` и `user_name` в `expo-secure-store`.

### M4. `Math.random()` для генерации Device ID и UUID
- **Файлы:**
  - `artifacts/messenger-android/utils/deviceId.ts:10-11`
  - `artifacts/messenger-android/app/chat/[id].tsx:11-14`
- **Проблема:** `Math.random()` не является криптографически стойким генератором. Device ID и idempotency key генерируются с его помощью.
- **Риск:** Предсказуемость ID может позволить атакующему подделать device ID или clientId для атаки на идемпотентность.
- **Исправление:** Использовать `expo-crypto` (`Crypto.randomUUID()`) или `expo-random` для генерации криптографически стойких случайных чисел.

### M5. Push token частично логируется в `console.log`
- **Файл:** `artifacts/messenger-android/services/notificationService.ts:69`
- **Проблема:** `console.log('[Push] Token registered:', token.slice(0, 32) + '…')` — логирует первые 32 символа push-токена.
- **Риск:** Push-токены могут быть перехвачены через логи устройства (logcat на Android).
- **Исправление:** Обернуть в `if (__DEV__)` или удалить полностью.

## LOW (5 находок)

### L1. Helmet `contentSecurityPolicy` отключён
- **Файл:** `artifacts/api-server/src/app.ts:14-18`
- **Пояснение:** Сервер отдаёт только JSON/WebSocket, не HTML — отключение CSP обосновано. Но для defense-in-depth стоит включить.

### L2. TURN-сервер с `verbose` логированием
- **Файл:** `deploy/coturn/turnserver.conf:17`
- **Пояснение:** Избыточное логирование может раскрыть информацию о WebRTC-соединениях. Рекомендуется убрать `verbose` в production.

### L3. Отсутствует заголовок `Permissions-Policy`
- **Файл:** `deploy/nginx/default.conf`
- **Пояснение:** Не ограничивает доступ браузера к камере/микрофону/геолокации. Рекомендуется добавить `Permissions-Policy` header.

### L4. Домен `chat.naviry.xyz` раскрывается в `.env.example`
- **Файл:** `deploy/.env.example:9,36`
- **Пояснение:** Домен в шаблоне раскрывает предполагаемый домен деплоя. Информационная находка.

### L5. keystore-пароль выводится в stdout скриптом `gen-keystore.sh`
- **Файл:** `scripts/gen-keystore.sh`
- **Пояснение:** Если скрипт запустить в CI, пароль попадёт в логи. Рекомендуется использовать только локально.
